# PyLot UI 与交互规范

本文档记录 PyLot 桌面端的页面职责、交互反馈和运行状态约定，作为开发与交付验收基线。

## 页面职责

- 脚本配置页：维护脚本配置并显示当前脚本实时输出。只有已保存脚本显示底部输出面板。
- 工作流编辑页：维护节点与依赖关系，不显示全局脚本输出。
- 工作流运行页：显示节点状态和当前工作流聚合输出；每行日志标识来源节点。
- 服务页：使用服务自己的 stdout/stderr 日志缓冲，不显示全局脚本输出。
- 定时任务页：展示定时规则和最近运行情况，不显示全局脚本输出。
- 设置页：首页和空状态均不显示输出面板。

## 操作反馈

- 用户点击后应立即进入 `启动中`、`停止中`、`保存中` 或 `处理中` 状态。
- 请求未完成前禁用重复提交，避免重复创建、删除或启动。
- 启停开关采用乐观更新；后端失败时恢复旧状态并显示错误。
- 服务状态以 `service:status` 事件为准，不使用固定延时刷新。
- 保存、运行、停止和删除失败时必须在当前操作区域显示可理解的错误信息。

## 保存与导航

- 新建脚本或工作流保存前不能运行或设置定时任务。
- 有未保存修改时，运行按钮不可用，避免用户误以为执行的是当前表单内容。
- 脚本、工作流、服务和设置存在未保存修改时，离开页面必须确认。
- 主题和字体即时生效；全局环境变量和飞书配置需要显式保存。

## 工作流

- 保存和运行前校验节点 ID、脚本引用、连线端点和循环依赖。
- 同一工作流不能重复启动。
- `StopWorkflow` 取消工作流上下文并停止当前运行层的脚本进程，最终状态为 `killed`。
- `workflow:node-status`、`workflow:status` 和 `workflow:log` 均携带 `workflowId`，前端只处理当前工作流事件。
- 删除工作流时同步移除使用负数 `script_id` 保存的定时规则和内存 scheduler job。
- 被工作流引用的脚本不能直接删除，必须先从工作流中移除。

## 定时任务

- 保存或启停规则时，数据库状态与内存 scheduler 注册必须保持一致。
- scheduler 注册失败时回滚数据库和旧任务状态。
- 保存弹窗只刷新一次定时概览；关闭弹窗不触发额外全量刷新。
- 每分钟只刷新定时概览和下次运行时间，历史记录由初次加载或用户手动刷新触发。
- 启停采用即时界面更新，删除成功后直接从本地列表移除。

## 设计系统

- 全局颜色、控件尺寸、圆角和状态色定义在 `frontend/src/style.css`。
- 通用按钮使用 `.ui-btn`，图标按钮使用 `.ui-icon-btn`，状态使用 `.ui-status`。
- 图标统一通过 `UiIcon.vue` 提供；确认操作统一使用 `ConfirmDialog.vue`。
- 页面必须同时支持深色和浅色主题，不得写死仅适用于单一主题的背景色。

## 验收命令

```powershell
go test ./...
cd frontend
npm run build
cd ..
wails build -platform windows/amd64 -ldflags "-H windowsgui"
```

正式构建输出为 `build/bin/PyLot.exe`。
